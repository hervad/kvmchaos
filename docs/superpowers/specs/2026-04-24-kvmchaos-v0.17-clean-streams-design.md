# kvmchaos v0.17 — Clean Observability Streams

**Date:** 2026-04-24
**Status:** Approved for implementation.
**Supersedes/extends:** `2026-04-23-kvmchaos-v0.16-observability-design.md`
**Resolves:** `docs/superpowers/followups/2026-04-24-observability-stderr-mixed-stream.md`
**Target version:** `v0.17.0`
**Branch:** `feat/v0.17-clean-streams`

## 1. Context

v0.16.0 shipped structured JSON events on stderr and to an optional webhook.
Lab validation on 2026-04-24 uncovered that stderr is not a pure JSONL stream:
it interleaves three kinds of non-JSON content with the structured events.

1. libvirt C-library error messages (e.g.
   `libvirt: Domain Config error : Requested operation is not valid: ...`)
   written directly to fd 2, bypassing Python's `logging` pipeline.
2. Typer `typer.echo(..., err=True)` human-readable error lines
   (e.g. `inject error: ...`, `step 1 failed (exit 1); continuing ...`).
3. Typer `typer.echo(..., err=True)` status lines
   (e.g. `Experiment finished with N failure(s).`).

Naive consumers (`jq .`, per-line JSON parsers, log shippers) crash on
these non-JSON lines. The current workaround is `jq -R 'fromjson? //
empty'`. This spec replaces the workaround with a first-class mechanism.

## 2. Goals

- G1. Provide a clean JSONL channel for automated consumers that requires
  no filtering or fragile parsing.
- G2. Stop leaking libvirt C-library diagnostics to stderr in the default
  INFO mode, without throwing the information away.
- G3. Preserve every existing v0.16 behavior. No breaking change to the
  stderr stream, the webhook payload, or run records.

## 3. Non-goals

- NG1. Moving Typer `echo(err=True)` human-readable messages off stderr.
  (They stay; users who need pure JSONL use the new channel.)
- NG2. Adding a new TOML configuration section or key.
  (CLI-only. Revisit if a second consumer asks for it.)
- NG3. Changing webhook payload shape or event catalog.
- NG4. Changing `experiment.end` status semantics.
- NG5. Log rotation of the `--json-log` file. Users rotate it themselves
  (`logrotate`, filename patterns, etc.).

## 4. Design

### 4.1 `--json-log PATH` root flag

A new option on the root Typer callback (`_root` in `cli.py`), alongside
`--verbose`:

```
--json-log PATH   Append structured events to PATH as pure JSONL.
```

Wiring:

- `configure_stderr_logging(*, verbose: bool, json_log_path: Path | None)`
  gains a second parameter. When `json_log_path` is set, it also attaches
  a `logging.FileHandler(json_log_path, mode="a", encoding="utf-8")` with
  the same `JsonFormatter` used for stderr.
- The file handler attaches to the same `kvmchaos.observability` logger,
  so any `emit()` call fans out to both stderr and file naturally.
- A `_kvmchaos_obs_file = True` sentinel attribute marks the handler for
  idempotent installation and clean tear-down in `reset_stderr_logging`.
- Append mode (`"a"`). The file is created if missing. Permission or
  OS-level open failure raises immediately at CLI startup, before any
  libvirt contact. The resulting message surfaces via
  `typer.echo(..., err=True)` with exit code 2 (usage error), consistent
  with existing `ConfigError` handling.

**File content guarantee.** Every line is a single JSON object followed by
`\n`. No prefixes, no non-JSON lines, no blank lines. This is the
contract users get when they pass `--json-log`.

### 4.2 libvirt error handler

Register a module-level handler in `libvirt_conn.py`, invoked once on
first `connect()`:

```python
_HANDLER_REGISTERED = False
_LIBVIRT_LOG = logging.getLogger("kvmchaos.observability.libvirt")

def _libvirt_error_handler(_ctx: object, err: tuple) -> None:
    code, domain, message, level, *_ = err
    _LIBVIRT_LOG.debug(
        message,
        extra={
            "event": "libvirt.stderr",
            "code": code,
            "domain": domain,
            "level": level,
        },
    )

def _register_once() -> None:
    global _HANDLER_REGISTERED
    if _HANDLER_REGISTERED:
        return
    libvirt.registerErrorHandler(_libvirt_error_handler, None)
    _HANDLER_REGISTERED = True
```

Called from `connect()` before `libvirt.open`. Effects:

- INFO mode (default) — libvirt C-library chatter is captured but not
  surfaced (DEBUG is below INFO). Clean stderr.
- `--verbose` mode — chatter appears as structured DEBUG JSON lines
  tagged `"event": "libvirt.stderr"`, trivially grep-able or filter-able.
- Python-level `libvirt.libvirtError` exceptions continue to propagate
  unchanged. Only the supplementary C-library fd-2 writes are captured.
- The `kvmchaos.observability.libvirt` logger is a child of
  `kvmchaos.observability`, so it inherits the handlers (stderr + file)
  already attached.

### 4.3 Data flow

```
emit(event)
  └─> kvmchaos.observability logger
        ├─> StreamHandler(stderr)          [always]
        └─> FileHandler(PATH, mode="a")    [if --json-log]

libvirt C-lib error
  └─> _libvirt_error_handler
        └─> kvmchaos.observability.libvirt logger (child; propagates up)
              ├─> StreamHandler(stderr)    [DEBUG — visible only with --verbose]
              └─> FileHandler(PATH)        [DEBUG — visible only with --verbose]
```

### 4.4 Error handling

| Condition | Behavior |
|---|---|
| `--json-log PATH` unwritable (permissions, dir missing) | Fail fast at CLI startup, exit 2, clear error message. |
| `--json-log` and `--verbose` combined | Both effects apply; file receives DEBUG events too. |
| libvirt C-lib call before `connect()` | Not possible — kvmchaos only enters libvirt through `connect()`. |
| Handler already registered (subsequent `connect()` calls, tests) | `_HANDLER_REGISTERED` guard makes re-registration a no-op. |

## 5. Testing

- `tests/test_cli_observability.py` — new cases:
  - `--json-log /tmp/.../x.jsonl` on a successful inject run: file exists,
    every line is valid JSON, event count matches stderr.
  - `--json-log /tmp/nonexistent-dir/x.jsonl`: exit 2, clear message, no
    libvirt calls made.
  - `--json-log` + `--verbose`: DEBUG records appear in file.
- `tests/test_libvirt_error_handler.py` — new file:
  - Call `_libvirt_error_handler` directly with a fake `err` tuple;
    assert one DEBUG record emitted with `extra["event"] ==
    "libvirt.stderr"` and the expected `code`, `domain`, `level`,
    `message`.
  - `_register_once()` is idempotent: two calls, still one registration.
- `tests/test_observability_logging.py` — existing tests remain green;
  new test that `configure_stderr_logging(json_log_path=...)` attaches a
  marked file handler and `reset_stderr_logging` removes it.
- No change needed to webhook or notifier tests.

**Coverage target:** maintain ≥85% per project policy; expect ≥95% on
the touched files.

## 6. Out of scope

Items from the followup's option set that are not being taken:

- Moving Typer error lines to stdout (option 3). Adds cognitive load
  without benefit given option 1 solves the stated problem.
- Third-file-descriptor approach (option 2). Clever but user-hostile.
- Silent libvirt suppression (option 4 as-written). Replaced by the
  DEBUG-capture variant above.
