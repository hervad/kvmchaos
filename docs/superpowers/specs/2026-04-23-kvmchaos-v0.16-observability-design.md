# kvmchaos v0.16 — Observability Design

**Date:** 2026-04-23
**Status:** Approved for planning
**Predecessor:** v0.15.0 (productisation: safety envelope, doctor, recipes)

## Goal

Give operators visibility into chaos runs without turning kvmchaos into a
long-running service. Two sinks, one event model:

1. **Structured stderr logs** — JSON lines, captured by journald when run
   under systemd, pipe-friendly (`| jq`) for ad-hoc CLI use.
2. **Webhook notifier** — single POST per event to a user-configured URL.
   Generic JSON schema; users wire their own Slack/Teams relay if needed.

Prometheus `/metrics`, Slack-native formatting, async queues, and retries are
deliberately out of scope (see §6).

## Non-goals

- Long-running daemon mode.
- Pull-based metrics (Prometheus, OpenMetrics).
- Per-target webhook routing.
- Authenticated/signed webhook delivery beyond a single bearer token.
- Multiple notifier endpoints.

## Architecture

Two new modules under `src/kvmchaos/observability/`:

- **`logging.py`** — installs a `JsonFormatter` on the root logger; emits one
  JSON object per record to stderr. Initialised once in `cli.main` before any
  command runs. Verbosity controlled by the existing `--verbose` flag
  (`INFO` default, `DEBUG` when set). No new runtime dep.
- **`notifier.py`** — single `Notifier` class. Reads `[notifier]` from
  `~/.config/kvmchaos/config.toml`. Exposes `notify(event: str, **fields)`.
  Synchronous `urllib.request.urlopen` POST, 3 s timeout. Failures are logged
  at `WARNING` and dropped; never re-raised.

Both sinks are passive. CLI command handlers (`inject_cmd`, `revert_cmd`,
`run_cmd`) emit events; observability modules never reach back into fault
state. The notifier is constructed once at CLI startup and passed to
handlers via the existing context object.

## Event model

Five events fire from the command handlers. The experiment runner (`run_cmd`)
wraps them with a sixth pair.

| Event              | Fired                                  | Extra fields                                       |
|--------------------|----------------------------------------|----------------------------------------------------|
| `inject.start`     | Before `fault.inject()`                | `fault`, `vm`, `params`, `duration_s`              |
| `inject.success`   | After successful inject                | `fault`, `vm`, `elapsed_s`                         |
| `inject.error`     | On `LibvirtError` / `CalledProcessError` | `fault`, `vm`, `error`, `error_type`             |
| `revert.success`   | After successful revert                | `fault`, `vm`, `elapsed_s`                         |
| `revert.error`     | On revert failure                      | `fault`, `vm`, `error`, `error_type`               |
| `experiment.start` | `run_cmd` begin                        | `recipe_path`, `step_count`                        |
| `experiment.end`   | `run_cmd` end                          | `recipe_path`, `status`, `elapsed_s`               |

Both sinks see the same events. JSON line shape (logging) and webhook body
shape are identical:

```json
{
  "event": "inject.start",
  "timestamp": "2026-04-23T21:31:05Z",
  "kvmchaos_version": "0.16.0",
  "host": "host.example.com",
  "fault": "net.latency",
  "vm": "rhel9-test",
  "params": {"ms": 200},
  "duration_s": 30
}
```

`timestamp` is ISO-8601 UTC. `host` is `socket.gethostname()`. `kvmchaos_version`
is read from `importlib.metadata.version("kvmchaos")` once at startup.

## Config

Extend `~/.config/kvmchaos/config.toml` with one new section. All fields
optional; absence of `webhook_url` disables the notifier entirely.

```toml
[notifier]
webhook_url = "https://example.internal/hooks/kvmchaos"
auth_header = "Bearer <token>"   # optional; sent verbatim as Authorization
timeout_s = 3                     # default 3
events = ["inject.start", "inject.error", "revert.error"]  # default: all
```

- `webhook_url` empty/absent → `Notifier.notify` is a no-op. No warning.
- `events` absent → all events fire.
- Malformed config (wrong types) → `ConfigError` raised in `Notifier.__init__`,
  matching the existing `[allowlist]` and `[rate_limit]` validation pattern.
  Fails before any fault runs.

Logging is always on; no config knob. Verbosity uses the existing
`--verbose` flag.

## Error handling

- **Notifier transport errors** (network failure, timeout, non-2xx response):
  caught inside `Notifier.notify`, logged at WARNING with `event` and
  exception type, then dropped. Chaos tool must never block recovery on a
  Slack/relay outage.
- **JSON serialisation** of `params` or arbitrary `extra` fields: the
  `JsonFormatter` coerces non-serialisable values via `str()`. Logging never
  raises.
- **Config errors**: fail fast at startup, before any fault is touched.

## Testing

- `tests/test_observability_logging.py`: capture stderr, assert each event
  line is valid JSON with required keys; assert `--verbose` toggles DEBUG
  records; assert non-serialisable `extra` values do not crash.
- `tests/test_observability_notifier.py`: patch `urllib.request.urlopen`.
  Cases: happy-path POST body shape and headers, `auth_header` passthrough,
  timeout swallowed, non-2xx swallowed, no-op when `webhook_url` empty,
  event filter respected, `ConfigError` on malformed config.
- `tests/test_cli_observability.py`: integration. Run
  `inject net.latency` end-to-end against `test:///default` with a mocked
  notifier; assert all expected events fired in order with correct fields.
  Same for `run_cmd` with a small recipe.
- Coverage target stays ≥85%. The 386-test v0.15 baseline must remain green.

## Out of scope (deliberate)

- Prometheus `/metrics` HTTP endpoint or pushgateway integration.
- Slack-native `blocks`/`attachments` formatting; Discord/Teams native shapes.
- Async or queued POSTs; retries; circuit breakers.
- Webhook signing (HMAC) beyond the single `auth_header` field.
- Multiple webhook endpoints or per-event routing.
- Pluggable notifier backends.

Each defers until a concrete user asks. Reopening any of these requires a
new design doc.

- [ ] All five inject/revert events plus the two experiment events fire from

- [ ] JSON log line and webhook body share one schema and match the example

- [ ] `Notifier` is a no-op when `webhook_url` is absent.
- [ ] Notifier transport failures never propagate.
- [ ] Malformed `[notifier]` config raises `ConfigError` at startup.
