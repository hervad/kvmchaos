# kvmchaos v0.1 — Design Spec

**Date:** 2026-04-20
**Status:** Draft — pending user review
**Author:** Vadym + Claude (brainstorming session)

---

## 1. Purpose

`kvmchaos` is a Python CLI that injects controlled, reversible faults into KVM/libvirt virtual machines from the hypervisor layer, without any guest-side agent. v0.1 ships two faults — `vm.pause` and `vm.kill` — as a minimal but end-to-end demonstration of the plugin architecture.

The tool is **single-user**, **Linux host only**, and **lab use only**. It is not a production chaos platform.

## 2. Non-Goals (v0.1)

- No GUI or web dashboard.
- No daemon mode; each invocation is a short-lived process.
- No multi-tenancy or authentication (libvirt socket permissions are the auth model).
- No remote libvirt (`qemu+ssh://…`) support yet — `--connect URI` accepts it, but only `qemu:///system` and `test:///default` are explicitly tested.
- No host-side privileged faults (tc, dmsetup, cgroups). Later version.
- No guest-side agent. Ever. Agent-less is the architectural identity.
- No external plugin system (entry points). A single in-repo registry dict is the plugin mechanism.

## 3. User-Facing CLI

```
kvmchaos --version
kvmchaos list-vms                         # list domains on the connected URI
kvmchaos list-faults                      # list registered fault names
kvmchaos inject <fault> <vm> [--yes] [--connect URI]
```

Behaviour of `inject`:

1. Resolve libvirt URI (precedence: `--connect` > `$LIBVIRT_DEFAULT_URI` > `qemu:///system`).
2. Look up `<fault>` in the registry. Unknown name → exit 2 with a list of valid names.
3. Look up `<vm>` as a libvirt domain. Missing → exit 2.
4. Prompt `About to inject '<fault>' on VM '<vm>'. Continue? [y/N]`. Skipped if `--yes`.
5. Run `fault.inject(domain)`, log event.
6. Run `fault.verify(domain)`, log event. On failure → attempt `revert()`, log, exit 1.
7. Run `fault.revert(domain)`, log event.
8. Exit 0 on full success.

Exit codes: `0` success, `1` runtime failure (libvirt error, verify failed), `2` usage error (unknown fault/VM, bad args).

## 4. Architecture

### 4.1 Module Layout

```
src/kvmchaos/
├── __init__.py          # __version__ constant
├── __main__.py          # enables `python -m kvmchaos`
├── cli.py               # Typer app: list-vms, list-faults, inject
├── libvirt_conn.py      # URI resolution + connection context manager
├── faults/
│   ├── __init__.py      # FAULTS registry dict
│   ├── base.py          # Fault Protocol (inject/verify/revert)
│   ├── vm_pause.py      # VmPauseFault
│   └── vm_kill.py       # VmKillFault
├── safety.py            # confirmation prompt
└── eventlog.py          # JSONL append-only event log
tests/
├── conftest.py          # pytest fixtures (test:///default connection)
├── test_cli.py
├── test_faults_vm_pause.py
├── test_faults_vm_kill.py
├── test_libvirt_conn.py
└── test_eventlog.py
docs/
└── superpowers/specs/   # this file lives here
```

Each module has a single responsibility. Faults do not import `cli`, `safety`, or `eventlog` — they receive a live `virDomain` object and return/raise. All orchestration lives in `cli.py`.

### 4.2 Fault Contract (`faults/base.py`)

Defined as a `typing.Protocol` so fault classes don't need to inherit a base class — they structurally match.

```python
class Fault(Protocol):
    name: ClassVar[str]          # e.g. "vm.pause"
    description: ClassVar[str]   # one-line human summary shown by list-faults
    destructive: ClassVar[bool]  # True for vm.kill, False for vm.pause

    def inject(self, domain: virDomain) -> None: ...
    def verify(self, domain: virDomain) -> None: ...  # raises on mismatch
    def revert(self, domain: virDomain) -> None: ...
```

Rationale for Protocol over ABC: zero inheritance, duck-typed, testable, aligns with modern Python (3.14+). Faults are stateless — all state lives on the `virDomain`.

### 4.3 Fault Registry (`faults/__init__.py`)

```python
from kvmchaos.faults.vm_pause import VmPauseFault
from kvmchaos.faults.vm_kill import VmKillFault

FAULTS: dict[str, Fault] = {
    VmPauseFault.name: VmPauseFault(),
    VmKillFault.name: VmKillFault(),
}
```

Adding a fault is: write the class, import it here, add one dict entry. No discovery magic, no decorators, fully grep-able.

### 4.4 Fault Semantics

| Fault | `inject()` | `verify()` | `revert()` | Notes |
|---|---|---|---|---|
| `vm.pause` | `domain.suspend()` | assert `state()[0] == VIR_DOMAIN_PAUSED` | `domain.resume()` | Freezes vCPUs; RAM retained. Guest clock will drift. |
| `vm.kill` | `domain.destroyFlags(VIR_DOMAIN_DESTROY_GRACEFUL)` | assert `state()[0] == VIR_DOMAIN_SHUTOFF` | `domain.create()` | Graceful-first (SIGTERM, then SIGKILL). Unsaved guest state lost. Requires domain to be persistently defined. |

Both faults check domain state **before** `inject` and refuse if the precondition is wrong (e.g. `vm.pause` on an already-paused domain). The check produces a clear error message and exit 2, not a silent no-op.

### 4.5 Libvirt Connection (`libvirt_conn.py`)

```python
@contextmanager
def connect(uri: str | None = None) -> Iterator[libvirt.virConnect]:
    resolved = uri or os.environ.get("LIBVIRT_DEFAULT_URI") or "qemu:///system"
    conn = libvirt.open(resolved)
    try:
        yield conn
    finally:
        conn.close()
```

Single connection per invocation. No thread-sharing (the Python binding is not thread-safe on the same `virConnect`). After opening, if the URI is `qemu:///system` and the domain list is empty and `$USER` is not in group `libvirt`, print a loud warning — this catches the silent `qemu:///session` trap that bites Fedora users.

### 4.6 Event Log (`eventlog.py`)

JSONL at `$XDG_STATE_HOME/kvmchaos/events.log`, defaulting to `~/.local/state/kvmchaos/events.log` when `XDG_STATE_HOME` is unset. Parent directory is created on first write.

Implementation: stdlib `logging` + custom `JsonFormatter` + `RotatingFileHandler` (10 MB, 3 backups). One logger `kvmchaos.events`. Line schema:

```json
{"ts":"2026-04-20T18:00:00+00:00","action":"inject","fault":"vm.pause","vm":"web1","result":"ok","duration_ms":42}
```

Fields: `ts` (ISO 8601 UTC), `action` (`inject`|`verify`|`revert`|`error`), `fault`, `vm`, `result` (`ok`|`fail`), `duration_ms`, optional `error` (string). No external deps (no `structlog`).

### 4.7 Safety (`safety.py`)

One function: `confirm(prompt: str, assume_yes: bool) -> bool`. Prints prompt, reads stdin, returns `True` on `y`/`yes` (case-insensitive). Returns `True` unconditionally if `assume_yes`. Default on empty input is `No`.

No allowlist in v0.1 — YAGNI for a two-VM lab.

## 5. Error Handling

- All `libvirt.libvirtError` raised during CLI orchestration is caught at the Typer command boundary, mapped to an actionable human message, and logged as an `error` event.
- Specific mappings: `VIR_ERR_NO_DOMAIN` → "VM '<name>' not found"; `VIR_ERR_AUTH_FAILED` / permission errors → "libvirt permission denied — is $USER in the `libvirt` group?"; connection refused → "libvirtd not running or URI unreachable: <uri>".
- If `verify()` fails after `inject()` succeeds, `cli.py` **attempts revert**, logs both, and exits 1. Never leave the VM in a verified-broken state on error if a revert path exists.
- If `revert()` itself fails, log loudly with `action=error` and exit 1. v0.1 does not retry.

## 6. Testing Strategy

**Primary test backend: `test:///default`** — libvirt's built-in in-process fake hypervisor, supporting real `virDomain` objects for create/destroy/suspend/resume. No mocks for happy paths.

- `conftest.py` provides a module-scoped `test_conn` fixture (open `test:///default`) and a function-scoped `test_domain` fixture that resets the bundled `test` domain to a known running state between tests.
- Fault unit tests assert on real state transitions against `test:///default`.
- Error-path tests use `MagicMock(spec=libvirt.virDomain)` to raise `libvirtError` with specific codes — the only place mocks appear.
- CLI tests use Typer's `CliRunner`; `list-vms` and `inject` exercise the `test:///default` backend end-to-end.
- No real `qemu:///system` in automated tests — only via manual smoke testing documented in README.

Target: >85% line coverage with `pytest-cov`. The 15% uncovered is expected to be the Fedora-warning branch of `libvirt_conn` (only triggers on a real system).

## 7. Dependencies

`pyproject.toml` runtime deps:

- `python >= 3.14`
- `libvirt-python >= 12.2.0` — requires `libvirt-devel` + `pkg-config` at install time (Fedora: `sudo dnf install libvirt-devel pkg-config`)
- `typer >= 0.12`

Dev deps:

- `pytest >= 8`
- `pytest-cov`
- `ruff` (lint + format)
- `ty` (type checker, per global CLAUDE.md)

No: `structlog`, `click` (Typer wraps it), `rich` (Typer uses it internally), `pydantic`, `aiovirt`.

Managed by `uv`. Lockfile committed.

## 8. Coding Standards

Per user request (level **C**): docstrings on all public classes, functions, and modules; inline comments reserved for non-obvious *why* only. Not a narrative of what each line does.

- Type hints on every function signature. `ty check` must pass with zero errors.
- `ruff check` and `ruff format` must pass with zero warnings — no rule suppressions without a `noqa` reason comment citing the rule code.
- Docstrings in Google style (one-line summary, blank line, optional longer body, `Args:`/`Returns:`/`Raises:` sections where meaningful).
- No commented-out code.
- Fail fast with clear messages; never silently catch `libvirtError`.
- ≤100 lines per function, cyclomatic complexity ≤8.

## 10. Acceptance Criteria for v0.1

- [ ] `kvmchaos --version` prints the version
- [ ] `kvmchaos list-vms` lists VMs on `qemu:///system` without sudo
- [ ] `kvmchaos list-faults` lists `vm.pause` and `vm.kill` with descriptions
- [ ] `kvmchaos inject vm.pause <vm>` pauses, verifies paused state, resumes — all three logged as JSONL events
- [ ] `kvmchaos inject vm.kill <vm>` destroys gracefully, verifies shut-off, restarts — all three logged
- [ ] Confirmation prompt blocks without `--yes`
- [ ] Unknown fault name → exit 2 with helpful error
- [ ] Missing VM → exit 2 with helpful error
- [ ] `pytest` passes; coverage ≥85%
- [ ] `ruff check`, `ruff format --check`, `ty check` all clean
- [ ] README install instructions work on a clean Fedora 43

## 11. Phase Structure (Post-v0.1)

v0.1 is scope-complete at the acceptance criteria above. After v0.1 ships, the following are sketched in `PLAN.md` as backlog, not committed: `net.latency` (tc), `disk.latency` (dm-delay), `migration.abort`, structured JSON-per-run records, HTML reports, remote libvirt, pre-commit hooks, CI.

Each adds real weight (subprocess, privilege escalation, file-per-run schema); each gets its own design spec when it becomes the next slice of work.

## 12. Open Questions (resolved in this design)

| Question | Resolution |
|---|---|
| Minimum fault set | `vm.pause` + `vm.kill` |
| Fault interface shape | `inject` + `verify` + `revert`, as `Protocol` |
| Plugin discovery | Explicit registry dict in `faults/__init__.py` |
| Safety guardrails | Confirmation prompt + `--yes`; no allowlist |
| Experiment records | JSONL append log, stdlib-only |
| CLI shape | Generic `inject <fault> <vm>`; no per-fault subcommands |
| Primary test backend | `test:///default` (real libvirt fake driver) |
| Comment policy | Docstrings on public API; inline comments only for non-obvious *why* |

## 13. Out-of-Scope Questions (deferred)

- Concurrent kvmchaos invocations against the same VM — deferred until a real fault class needs it.
- Revert retry/backoff behaviour — v0.1 logs and exits; future work.
- Experiment YAML schema — deferred to post-v0.1.
- Privilege model for host-side faults — deferred to when the first such fault lands.
- Project naming (`kvmchaos` vs alternatives) — deferred until a public release is contemplated.
