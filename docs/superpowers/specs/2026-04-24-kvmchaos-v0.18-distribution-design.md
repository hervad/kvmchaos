# kvmchaos v0.18 — Distribution Design Spec

**Date:** 2026-04-24
**Status:** Draft

## 1. Goal

Install kvmchaos on an air-gapped RHEL 9 KVM host with one command:

```bash
rpm -i kvmchaos-0.18.0-1.el9.x86_64.rpm
```

No internet access, no Python version dependency, no virtualenv management on the target host.

## 2. Scope

- Self-contained binary RPM (PyInstaller `--onefile` → `rpmbuild`)
- Bash completion installed via RPM
- No PyPI publish (production is air-gapped; no public audience)

Out of scope: zsh completion, container image, multi-arch builds.

## 3. Constraints

- **Target:** RHEL 9 KVM host (glibc 2.34, x86_64). No internet access.
- **Build environment:** `almalinux:9` container — identical ABI to RHEL 9, freely available on Docker Hub.
- **Why not Fedora 43:** glibc 2.38 — binaries built there will not run on RHEL 9 (glibc 2.34).
- **Runtime dep:** `libvirt.so` stays as a system library (`Requires: libvirt-libs` in RPM). Already present on any KVM host.
- **Python on host:** irrelevant — PyInstaller bundles the runtime from the build container.

## 4. Build Pipeline

Triggered on tag push alongside the existing `build-wheel` job. New `build-rpm` job runs in `almalinux:9` container.

### Steps

1. Checkout source.
2. Install build tools: `python3.11`, `python3.11-pip`, `rpm-build` from AlmaLinux 9 repos.
3. `pip install pyinstaller && pip install uv && uv sync`.
4. Run `packaging/build.sh`:
   a. `pyinstaller --onefile --name kvmchaos --collect-all kvmchaos -m kvmchaos.cli`
   b. `./dist/kvmchaos --show-completion bash > packaging/kvmchaos-bash-completion`
   c. `rpmbuild -bb packaging/kvmchaos.spec`
5. Upload `~/rpmbuild/RPMS/x86_64/kvmchaos-*.rpm` to GitHub Release.

### Local build

`packaging/build.sh` can be run locally (in an AlmaLinux 9 container or VM) to reproduce the CI build without pushing a tag.

## 5. RPM Spec (`packaging/kvmchaos.spec`)

```
Name:    kvmchaos
Version: %{version}
Release: 1%{?dist}
Summary: KVM chaos engineering CLI
License: MIT
Requires: libvirt-libs

%description
kvmchaos injects and reverts KVM faults (vm.pause, net.latency, disk.latency,
etc.) via libvirt. Declarative experiments, structured event logging, safety
allowlist and rate limiting.

%install
install -Dm755 %{_sourcedir}/kvmchaos          %{buildroot}%{_bindir}/kvmchaos
install -Dm644 %{_sourcedir}/kvmchaos-bash-completion \
               %{buildroot}%{_sysconfdir}/bash_completion.d/kvmchaos

%files
%{_bindir}/kvmchaos
%{_sysconfdir}/bash_completion.d/kvmchaos
```

`%{version}` is injected by `rpmbuild -D "version <X.Y.Z>"` in `build.sh`.

## 6. Install Layout on Host

```
/usr/bin/kvmchaos
/etc/bash_completion.d/kvmchaos
```

No Python, no virtualenv, no config files installed by the RPM. Existing
`~/.config/kvmchaos/config.toml` is user-managed and untouched by install/remove.

## 8. Version

v0.18.0. Version bump + CHANGELOG entry is task 1 of the implementation plan.

## 9. Acceptance Criteria

- `rpm -i kvmchaos-0.18.0-1.el9.x86_64.rpm` installs cleanly on RHEL 9 with no Python or pip present
- `kvmchaos --version` prints `0.18.0`
- `kvmchaos --help` lists all subcommands
- `kvmchaos list-faults` works against `qemu:///system`
- Bash completion loads after `source /etc/bash_completion.d/kvmchaos`
- `rpm -e kvmchaos` removes both installed files cleanly
- GitHub Release contains `kvmchaos-0.18.0-1.el9.x86_64.rpm` alongside the wheel
