# kvmchaos v0.2 Design — vm.freeze, vm.starve, --dry-run

**Date:** 2026-04-21
**Status:** Approved

## Summary

Three additions to kvmchaos v0.1:

1. `vm.freeze` — CPU throttle via libvirt `setCpuSchedulerParameters`
2. `vm.starve` — Memory squeeze via libvirt balloon (`setMemory`)
3. `--dry-run` flag on `inject` — full validation, no mutation

All three fit the existing `Fault` protocol and agentless design without changes to
`base.py`, `eventlog.py`, `safety.py`, or `libvirt_conn.py`.

## Decisions

| Decision | Choice | Rationale |
|---|---|---|
| vm.freeze implementation | Libvirt API (`setCpuSchedulerParameters`) | Consistent with existing faults; no subprocess |
| vm.starve scope | Host-side balloon (agentless) | Keeps agentless design; renamed from "stress injection" |
| --dry-run validation depth | Full: connect + VM lookup, no mutation | Catches bad args and connectivity without side effects |
| --dry-run integration | `dry_run: bool` in `_run_step` | Minimal surface; zero fault changes needed |
| vm.freeze revert value | Hardcoded 1024 (QEMU/KVM default cpu_shares) | Faults are stateless singletons; no stored state |
| vm.starve revert target | `domain.maxMemory()` read at revert time | Stateless; always correct regardless of timing |

## Components

### vm.freeze (`faults/vm_freeze.py`)

Throttles the VM's CPU scheduler shares to the minimum (2), causing the guest to
receive near-zero CPU time. Reverts to the QEMU/KVM default of 1024.

| Step | Libvirt call | Success condition |
|---|---|---|
| inject | `domain.setCpuSchedulerParameters({"cpu_shares": 2})` | No exception |
| verify | `domain.getCpuSchedulerParameters()` | `cpu_shares == 2` |
| revert | `domain.setCpuSchedulerParameters({"cpu_shares": 1024})` | No exception |

**Metadata:**
- `name = "vm.freeze"`
- `description = "Throttle CPU shares to minimum; guest runs near-zero speed."`
- `destructive = False`

**Error handling:** `libvirtError` from any step propagates to `_run_step`, which logs
`result="fail"` and re-raises. `verify` raises `RuntimeError` if shares are not 2.

**Caveat:** If the user had a non-default `cpu_shares` before inject, revert restores
to 1024, not the original value. Documented in the description.

### vm.starve (`faults/vm_starve.py`)

Balloons the VM's memory to 25% of its configured maximum, causing the guest OS to
swap heavily. Reverts by ballooning back to the configured maximum.

| Step | Libvirt call | Success condition |
|---|---|---|
| inject | `domain.setMemory(domain.maxMemory() // 4)` | No exception |
| verify | `domain.memoryStats()["rss"] <= domain.maxMemory() * 0.5` | Within loose bound |
| revert | `domain.setMemory(domain.maxMemory())` | No exception |

**Metadata:**
- `name = "vm.starve"`
- `description = "Balloon memory to 25% of max; guest swaps heavily."`
- `destructive = False`

**Error handling:** If the guest has no balloon driver, `setMemory` raises
`libvirtError` — propagates normally. `verify` uses a 50% bound to accommodate
balloon driver settling latency.

**Note:** `maxMemory()` is read fresh at each step — no instance state stored.

### --dry-run flag (`cli.py`)

Added to `inject_cmd` as `--dry-run / -n`. Propagated to `_run_step` as
`dry_run: bool`.

**Behaviour:**
- Opens libvirt connection normally.
- Looks up domain by name normally.
- Calls `confirm()` normally (or skips with `--yes`).
- `_run_step` with `dry_run=True`: prints `[dry-run] would: <action> <fault> on <vm>`
  and returns immediately without calling the fault method.
- Nothing written to the event log during a dry run.

**Exit codes** are unchanged: unknown fault → 2, unknown VM → 2, user aborts → 1.

## Testing

**vm.freeze / vm.starve:** `MagicMock(spec=libvirt.virDomain)` for all tests —
`test:///default` does not implement `getCpuSchedulerParameters` or balloon calls
(QEMU-specific APIs). All assertions are on mock call args.

**--dry-run CLI tests:** Typer `CliRunner` with `test:///default` URI via
`--connect test:///default`.

### vm.freeze tests
- `inject` calls `setCpuSchedulerParameters({"cpu_shares": 2})`
- `verify` passes when `getCpuSchedulerParameters` returns `{"cpu_shares": 2}`
- `verify` raises `RuntimeError` when shares ≠ 2
- `revert` calls `setCpuSchedulerParameters({"cpu_shares": 1024})`
- `libvirtError` from inject propagates

### vm.starve tests
- `inject` calls `setMemory` with 25% of `maxMemory()` return value
- `verify` passes when `memoryStats` returns `{"rss": <low value>}`
- `verify` raises `RuntimeError` when RSS > 50% of max
- `revert` calls `setMemory` with `maxMemory()` return value
- `libvirtError` from inject propagates

### --dry-run CLI tests
- Valid fault + existing VM → exit 0, stdout contains `[dry-run]` lines, no mutation
- Unknown fault with `--dry-run` → exit 2
- Unknown VM with `--dry-run` → exit 2
- `--dry-run --yes` skips confirmation and prints plan
